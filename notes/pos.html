1. Define an Operating System. Explain any four functions of an Operating System. ⭐ IMP

Definition
An Operating System (OS) is a system software that acts as an intermediate between the user and computer hardware.

Importance of Operating System
1. Acts as a bridge between user and hardware.
2. Improves system efficiency and performance.
3. Enables multitasking and resource sharing.

Functions of Operating System
1. Process Management
The OS manages all processes (programs in execution). It creates, schedules, and terminates processes. It allocates CPU time and ensures smooth multitasking.
2. Memory Management
The OS manages the computer's main memory (RAM). It allocates memory to different programs, tracks memory usage, and deallocates memory when no longer needed.
3. File System Management
The OS organizes and manages files and directories. It allows users to create, delete, rename, copy, and access files efficiently.
4. Secondary Storage Management
The OS manages storage devices such as hard disks and SSDs. It handles storage allocation, free-space management, and disk scheduling.
5. Device Management
The OS manages all input and output devices such as keyboards, printers, monitors, scanners, and disk drives. It uses device drivers to communicate with hardware, allocates devices to processes, and controls device operations efficiently.
6. Security and Protection
The OS protects system resources and user data through authentication, passwords, access control, and security mechanisms that prevent unauthorized access.
7. Networking
The OS enables communication between computers through network protocols. It supports internet access, file sharing, and resource sharing over networks.
8. Error Detection and Handling
The OS continuously monitors the system for hardware and software errors. It detects faults and takes corrective actions to maintain system stability.

2. Explain the different Operating System services provided to users and programs. ⭐ IMP

An Operating System (OS) is a system software that acts as an intermediate between the user and computer hardware.

Importance of Operating System Services
Operating system services provide a convenient environment for users and applications to perform tasks efficiently. They ensure proper resource management, security, communication, and smooth execution of programs.

Operating System Services
1. User Interface (UI)
The operating system provides an interface through which users interact with the computer.
Types: 1. GUI (Graphical User Interface): Uses windows, icons, menus, and pointers. 2. CLI (Command Line Interface): Uses text-based commands.
Example: Windows GUI, Linux Terminal.

2. Program Execution
The OS loads programs into memory, executes them, and terminates them after completion.
Example: Opening and running Microsoft Word or a web browser.

3. I/O Operations
The operating system manages input and output devices such as keyboards, printers, scanners, and monitors.
Example: Printing a document using a printer.

4. File System Manipulation
The OS manages files and directories by allowing users to create, delete, rename, read, and write files.
Example: Creating a new folder and saving documents in it.

5. Communication
The operating system enables communication between processes and between computers over a network.
Example: Sending an email or sharing files through a network.

6. Error Detection and Handling
The OS detects hardware and software errors and takes corrective actions to maintain system stability.
Example: Displaying an error message when a file cannot be opened.

7. Resource Allocation
The operating system allocates system resources such as CPU, memory, storage, and devices among multiple users and processes.
Example: Running multiple applications simultaneously without conflicts.

3. What are system calls? Explain any four types of system calls with examples. ⭐ IMP

A System Call is a mechanism through which a user program requests services from the Operating System kernel.

Importance of System Calls
System calls are essential because they provide a secure and controlled interface between user programs and the operating system kernel. They enable applications to access hardware resources and perform operations such as file handling, process management, device control etc.

Types of System Calls
1. Process Control System Calls
These system calls are used for process creation, execution, and termination. They help in managing processes running in the system.
Examples: 1. fork() - Creates a new process. 2. exit() - Terminates a process.
Use: Creating and managing multiple processes.

2. File Management System Calls
These system calls perform operations on files such as creating, opening, reading, writing, and deleting files.
Examples: 1. open() - Opens a file. 2. write() - Writes data to a file.
Use: Managing files and directories.

3. Device Management System Calls
These system calls control and communicate with hardware devices such as printers, keyboards, scanners, and disk drives.
Examples: 1. read() - Reads data from a device. 2. ioctl() - Controls device-specific operations.
Use: Handling input/output devices efficiently.

4. Information Maintenance System Calls
These system calls provide information about the system and manage system-related data.
Examples: 1. time() - Gets current system time. 2. uname() - Retrieves system information.
Use: Obtaining system and process information.

5. Communication System Calls
These system calls enable communication between processes, either on the same computer or across a network.
Examples: 1. pipe() - Creates a communication channel. 2. send() Sends messages.
Use: Inter-process communication (IPC) and networking.

5. What is a process? Explain the different states of a process with a suitable diagram.

A process is a program that is currently being executed. It is an active entity that requires CPU, memory, and other system resources to perform its task. A process contains the program code, data, current activity, and information required by the operating system to manage its execution.

During its lifetime, a process passes through different states depending on whether it is being created, waiting for the CPU, executing, waiting for I/O, or completing its execution.

Different States of a Process
A process generally passes through the following five states:

1. New: The process is being created. The operating system creates the necessary resources and prepares the process for execution.
2. Ready: The process is ready to execute and is waiting for the CPU to be assigned to it. It is placed in the ready queue.
3. Running: The process is currently being executed by the CPU. At a particular time, a CPU core can execute one process at a time.
4. Waiting/Blocked: The process is temporarily unable to continue its execution because it is waiting for an event, such as completion of an I/O operation or availability of a required resource.
5. Terminated: The process has completed its execution or has been stopped by the operating system. The resources allocated to the process are then released.

State Transitions
The process changes from one state to another according to different events. When a new process is admitted, it enters the Ready state. The CPU scheduler then selects a ready process and moves it to the Running state. If the process requests I/O, it moves to the Waiting state. After the I/O operation is completed, it returns to the Ready state. Finally, when the process completes its execution, it moves to the Terminated state.

Conclusion
The process states help the operating system manage CPU and system resources efficiently. By keeping track of the current state of every process, the operating system can decide which process should run, which processes need to wait, and when resources can be released.

6. Explain process scheduling. What are the different scheduling queues used by an Operating System?

Process Scheduling
Process scheduling is the activity of the Operating System that selects a process from the ready queue and allocates the CPU to it for execution. Since many processes may be present in the system at the same time but the CPU can execute only a limited number of processes at once, scheduling is required to decide which process should run next.

The main purpose of process scheduling is to keep the CPU busy and improve system performance. The component of the OS that selects the next process is called the CPU scheduler or short-term scheduler.

Different Scheduling Queues
An Operating System generally uses the following scheduling queues:

1. Job Queue:
It contains all the processes that are present in the system and are waiting to be admitted for execution. It includes processes stored on secondary storage.
2. Ready Queue:
It contains processes that are ready to execute and are waiting for CPU allocation. The CPU scheduler selects a process from this queue.
3. Device Queue:
It contains processes that are waiting for a particular I/O device such as a printer, keyboard, disk, or network device. A separate device queue may exist for each I/O device.

When a process is created, it enters the job queue. After being admitted to memory, it enters the ready queue. The CPU scheduler selects a process from the ready queue and assigns the CPU to it. If the process requires I/O, it moves to the appropriate device queue and returns to the ready queue after completing the I/O operation.
Thus, process scheduling and scheduling queues help the Operating System manage processes efficiently and utilize the CPU and other resources effectively.

7. What are threads? Explain the advantages of multithreading.

Threads
A thread is the smallest unit of execution within a process. A process can contain one or more threads, and each thread performs a separate task.

Threads of the same process share resources such as code, data, and files, but each thread has its own program counter, registers, and stack.
For example, a web browser may use different threads for loading a webpage, playing a video, and responding to user input.

Multithreading
Multithreading is the ability of a process to execute multiple threads concurrently. It allows different tasks of the same process to run at the same time, improving the performance and responsiveness of the system.

Advantages of Multithreading

1. Improved Responsiveness:
Multithreading allows one part of an application to continue working even when another thread is busy. This makes applications more responsive.
2. Better CPU Utilization:
When one thread is waiting for I/O, another thread can use the CPU. This reduces CPU idle time.
3. Resource Sharing:
Threads of the same process share memory and other resources. Therefore, communication between threads is easier than between separate processes.
4. Faster Execution:
Multiple threads can execute concurrently, and on a multi-core processor they may run in parallel, reducing the time required to complete tasks.
5. Economy:
Creating and managing threads generally requires fewer resources than creating separate processes.

Thus, multithreading improves responsiveness, CPU utilization, resource sharing, and overall performance of an Operating System and applications.

8. What is a Race Condition? Explain the Critical-Section Problem with a suitable example. ⭐ IMP

Race Condition
A race condition occurs when two or more processes or threads access and modify a shared resource at the same time. The final result depends on the order of execution and may be incorrect.

Critical-Section Problem
A critical section is the part of a program where a process accesses or modifies a shared resource, such as a variable, file, or memory.

The Critical-Section Problem is to ensure that processes can access shared resources safely without causing data inconsistency.

A solution should satisfy:
Mutual Exclusion: Only one process can execute its critical section at a time.
Progress: A process should be allowed to enter the critical section when it is free.
Bounded Waiting: A process should not wait indefinitely.

Example
Suppose two processes, P1 and P2, update the same variable X = 5.

Shared Variable X = 5
P1P2
X = X + 1X = X + 1
Final X = 6

Both processes may read X = 5 before either writes the updated value. Therefore, the final value may become 6 instead of 7. This is a race condition.

The problem can be prevented using synchronization mechanisms such as mutex locks and semaphores, which allow only one process to access the critical section at a time.
Thus, the Critical-Section Problem helps prevent race conditions and maintains consistency of shared data.

9. What is a Mutex Lock? Explain how Mutex Locks are used for Process Synchronization. ⭐ IMP

Mutex Lock
A mutex (Mutual Exclusion) lock is a synchronization mechanism used in an Operating System to ensure that only one process or thread can access a shared resource at a time. It prevents multiple processes from modifying shared data simultaneously.

A mutex lock has two basic operations:
1. Acquire/Lock: A process obtains the lock before entering the critical section. If the lock is already held by another process, the process waits.
2. Release/Unlock: After completing its work in the critical section, the process releases the lock so that another waiting process can access the resource.

Use of Mutex Lock for Process Synchronization
Mutex locks are mainly used to protect the critical section, where shared resources such as files, variables, or memory are accessed.

Example:
Suppose two processes, P1 and P2, want to update the same bank account balance.

Shared Resource: Bank Account Balance
P1P2
Acquire LockWait for Lock
Critical Section
Update Balance
Release LockP2 gets Lock

Here, P1 acquires the mutex lock and updates the balance. P2 must wait until P1 releases the lock. This prevents both processes from changing the balance at the same time.

Mutex locks are especially useful when multiple processes or threads share the same data or resources. By allowing only one process to enter the critical section at a time, a mutex ensures that shared data remains consistent and prevents unexpected results caused by simultaneous access.
Thus, mutex locks provide mutual exclusion and help prevent race conditions and data inconsistency during process synchronization.

10. What is a semaphore? Explain the wait() and signal() operations with an example. ⭐ IMP

Semaphore
A semaphore is a synchronization mechanism provided by an Operating System to control access to shared resources by multiple processes or threads. It is an integer variable that helps prevent problems such as race conditions when processes access the same resource at the same time.

A semaphore can be accessed only through two main atomic operations: wait() operation and signal() operation.

1. wait() Operation
The wait() operation is performed when a process wants to enter the critical section or use a shared resource. It decreases the value of the semaphore by 1.

wait(S)
{
    while (S<=0)
        wait;
    S--;
}

If the semaphore value is greater than 0, the process can continue and access the resource. If the value is 0, the process has to wait until the resource becomes available.

2. signal() Operation
The signal() operation is performed when a process has finished using the shared resource. It increases the semaphore value by 1 and allows another waiting process to use the resource.

signal(S)
{
    S++;
}

Example
Consider a system having one printer shared by two processes, P1 and P2. Since there is only one printer, only one process should use it at a time. Therefore, we initialize the semaphore as: S = 1

The working can be represented as:
Semaphore S=1
P1 calls wait(S)
S=0
P1 uses Printer
P1 calls signal(S)
S=1
P2 can use Printer

When P1 calls wait(S), the semaphore becomes 0 and P1 gets access to the printer. If P2 tries to use the printer at the same time, it has to wait because the semaphore value is 0. After P1 completes its printing, it calls signal(S), which changes the value back to 1. P2 can then access the printer.
Thus, semaphores are important for process synchronization because they control access to shared resources and help prevent conflicts between processes.

11. Explain Reader-Writer Problem.

The Reader-Writer Problem is a classical process synchronization problem in which multiple processes share a common data resource such as a file or database.

There are two types of processes:
Reader: Only reads the shared data. Multiple readers can read the data at the same time.
Writer: Modifies the shared data. A writer must have exclusive access, so no reader or other writer can access the data while it is writing.

Working
When one or more readers are reading, other readers can also read simultaneously. However, when a writer is accessing the shared data, all other readers and writers must wait.

For example, suppose several users are reading a student database. All users can read the database at the same time. But when an administrator updates the database, other users must wait until the update is completed.
The problem is solved using semaphores, mutex locks, or other synchronization mechanisms.
Thus, the Reader-Writer Problem ensures safe access to shared data while allowing multiple readers to work simultaneously.

1. What is a deadlock? Explain the four necessary conditions for deadlock with suitable examples. ⭐ IMP

Definition of Deadlock
A deadlock is a situation in an operating system where two or more processes are permanently blocked, because each process is waiting for a resource held by another process.

Example
Consider two processes P1 and P2 and two resources R1 and R2:
P1 holds R1 and is waiting for R2.
P2 holds R2 and is waiting for R1.

P1 —holds—> R1
↑           |
|           ↓
R2 <—holds— P2

P1 waits for R2
P2 waits for R1

Therefore, both processes wait indefinitely, resulting in a deadlock.

Four Necessary Conditions for Deadlock
Deadlock can occur only when all four of the following conditions exist simultaneously:

1. Mutual Exclusion
Mutual exclusion means that a resource can be used by only one process at a time.
If one process is using a resource, another process cannot use the same resource until it is released.
Example
Suppose there is only one printer in a system.
P1 is using the printer.
P2 requests the printer.
P2 must wait until P1 releases it.

Printer → P1
          ↓
       P2 waits

Thus, the printer is a non-shareable resource, satisfying the mutual exclusion condition.

2. Hold and Wait
Hold and wait means that a process is holding at least one resource while waiting to acquire another resource.
The process does not release the resource it already has while waiting for the additional resource.
Example
Suppose:
P1 has acquired the printer.
P1 is still holding the printer.
P1 is waiting for the scanner.

P1
├── holds → Printer
└── waits → Scanner

If another process holds the scanner and waits for the printer, a deadlock can occur.

3. No Preemption
No preemption means that a resource cannot be forcibly taken away from a process that is currently holding it.
The process must release the resource voluntarily after completing its operation.
Example
Suppose P1 is using a printer.
The operating system cannot simply take the printer away from P1 in the middle of a printing operation and give it to P2.

P1 → using Printer

P2 → requests Printer
          ↓
         Wait

P1 must finish its operation and release the printer.
Therefore, the resource cannot be forcibly preempted.

4. Circular Wait
Circular wait occurs when a circular chain of processes exists in which each process is waiting for a resource held by the next process in the chain.
Example
Suppose there are two processes and two resources:
P1 holds R1 and waits for R2.
P2 holds R2 and waits for R1.

P1 —waits for—> R2
↑               |
|               ↓
R1 <—held by——— P2

P1 cannot proceed until P2 releases R2, while P2 cannot proceed until P1 releases R1.
Hence, they remain blocked indefinitely.

2. Explain the different methods for handling deadlocks. Compare deadlock prevention, avoidance, detection and recovery. ⭐ IMP

Definition of Deadlock
A deadlock is a situation in an operating system where two or more processes are permanently blocked, because each process is waiting for a resource held by another process.

Operating systems use four main methods to handle deadlocks: prevention, avoidance, detection, and recovery.

1. Deadlock Prevention
Deadlock prevention is a method in which the operating system ensures that at least one of the four necessary conditions for deadlock never occurs.
The four conditions are:
Mutual Exclusion
Hold and Wait
No Preemption
Circular Wait
Example: The OS can prevent hold and wait by requiring a process to request all the resources it needs at once.
Advantage: Deadlock is completely prevented.
Disadvantage: It may result in low resource utilization and reduced system performance.

2. Deadlock Avoidance
Deadlock avoidance allows the necessary conditions to exist but ensures that the system never enters an unsafe state.
Before allocating a resource, the OS checks whether the allocation will keep the system safe.
The most common method is the Banker's Algorithm.
Advantage: Provides better resource utilization.
Disadvantage: The maximum resource requirements of processes must be known in advance.

3. Deadlock Detection
In this method, the OS allows deadlocks to occur and periodically checks the system to determine whether a deadlock exists.
A Wait-for Graph or other deadlock detection algorithms can be used.
Advantage: Resources can be allocated more freely.
Disadvantage: A deadlock may occur before it is detected.

4. Deadlock Recovery
Once a deadlock is detected, the OS takes action to break the deadlock and restore normal operation.
Common recovery methods include:
Process termination: Terminate one or more processes involved in the deadlock.
Resource preemption: Take resources from selected processes and allocate them to others.

3. Explain deadlock prevention. How can each of the four necessary conditions for deadlock be prevented? ⭐ IMP

Definition
Deadlock prevention is a technique in which the operating system ensures that at least one of the four necessary conditions for deadlock never occurs.
By breaking any one condition, deadlock can be prevented.

The four necessary conditions and their prevention methods are:

1. Prevent Mutual Exclusion
Make resources sharable wherever possible.
Multiple processes can access the resource simultaneously if the resource permits it.
However, some resources, such as printers, cannot be easily shared.

2. Prevent Hold and Wait
A process should not hold one resource while waiting for another.
This can be prevented by:
Requiring a process to request all required resources at once before execution.
Making a process release its currently held resources before requesting new resources.
Example: A process must request both a printer and scanner together instead of holding the printer while waiting for the scanner.

3. Prevent No Preemption
Resources can be preempted (taken away) from a process when necessary.
If a process requests a resource that is unavailable, its currently held resources may be released and allocated again later.
Example: If P1 cannot obtain a required resource, the OS may force P1 to release the resources it currently holds.

4. Prevent Circular Wait
Assign a fixed ordering to all resource types.
Processes must request resources only according to this order.
Example: If the order is R1 < R2 < R3, a process must request R1 before R2 and R2 before R3. This prevents a circular chain of waiting.

4. Explain deadlock avoidance and describe the Banker's Algorithm with its basic steps. ⭐ IMP

Definition
Deadlock avoidance is a technique in which the operating system allocates resources carefully so that the system never enters an unsafe state.
Unlike deadlock prevention, it does not necessarily eliminate the four necessary conditions. Instead, the OS checks each resource request before granting it.
The most important deadlock avoidance algorithm is the Banker's Algorithm.

Banker's Algorithm
The Banker's Algorithm is used when the OS knows the maximum resource requirements of each process in advance. It works like a bank that gives loans only when it is sure that all customers can eventually be satisfied.

Basic Steps

Step 1: Check the Resource Request
When a process requests resources, the OS first checks whether the request is within the process's remaining declared requirement.
Request ≤ Need
If the request is greater than the remaining need, the request is considered invalid.

Step 2: Check Resource Availability
The OS checks whether the requested resources are currently available.
Request ≤ Available
If sufficient resources are not available, the process must wait.

Step 3: Pretend to Allocate the Resources
If the resources are available, the OS temporarily assumes that the resources are allocated to the requesting process.
The values are updated as:
Available = Available − Request
Allocation = Allocation + Request
Need = Need − Request

Step 4: Check for Safe State
The OS checks whether all processes can still complete successfully.
If the system remains safe, the request is granted.
If the system becomes unsafe, the request is denied and the process must wait.

Important Terms
Available: Number of resources currently available in the system.
Maximum: Maximum number of resources that a process may require.
Allocation: Number of resources currently allocated to a process.
Need: Number of additional resources required by a process to complete.
The formula is: Need = Maximum − Allocation

Example
Suppose process P1 has:
Maximum requirement: 10
Currently allocated: 4
Therefore:
Need = Maximum − Allocation
Need = 10 − 4 = 6
Thus, P1 may still require 6 more resources to complete.
The OS will grant additional resources only if doing so keeps the system in a safe state.

Safe State
A system is in a safe state if there is at least one sequence of processes in which every process can obtain its remaining resources and complete successfully without causing a deadlock.
A safe sequence can be represented as: P1 → P2 → P3 → ⋯
If such a sequence exists, the system is safe.

8. What is demand paging? Explain the steps involved in handling a page fault.

Definition
Demand paging is a memory management technique in which a page is loaded into main memory (RAM) only when it is required by the executing process.
In demand paging, all pages of a process do not need to be loaded into memory at the beginning. Only the required pages are brought into memory. This saves memory and allows more processes to be kept in main memory.

Page Fault
A page fault occurs when a process tries to access a page that is not currently present in main memory.
When this happens, the operating system must bring the required page from secondary storage into RAM before the process can continue.

Steps Involved in Handling a Page Fault

Step 1: Generate a Memory Reference
The CPU generates a logical address and tries to access the required page.

Step 2: Check the Page Table
The operating system checks the page table to determine whether the required page is currently present in main memory.

Step 3: Page Fault Occurs
If the page is not present in memory, a page fault trap is generated, and control is transferred to the operating system.

Step 4: Check the Validity of the Reference
The OS checks whether the memory reference is valid.
If the reference is invalid, the process is terminated or an appropriate error is generated.

Step 5: Find a Free Frame
If the reference is valid, the OS searches for a free frame in main memory.
If no free frame is available, the OS selects a page for removal using a page replacement algorithm.

Step 6: Load the Required Page
The required page is brought from secondary storage into the selected free frame.

Step 7: Update the Page Table
The OS updates the page table to indicate that the page is now present in main memory and records the corresponding frame number.

Step 8: Restart the Interrupted Instruction
The instruction that caused the page fault is restarted, and the process continues its execution normally.

Example
Suppose a process needs to access Page 5, but Page 5 is not present in RAM.
A page fault occurs. The OS finds a free frame, loads Page 5 from secondary storage into that frame, updates the page table, and then restarts the interrupted instruction.

9. Explain page replacement. Describe any two page replacement algorithms with suitable examples.

Page Replacement
Page replacement is a technique used in virtual memory when a page required by a process is not present in main memory. This situation is called a page fault.
When all available frames are occupied, the operating system must select one existing page and replace it with the required page. The main aim of page replacement is to reduce the number of page faults and improve system performance.

Page Replacement Process
1. A process requests a page.
2. If the page is not in memory, a page fault occurs.
3. If no free frame is available, the OS selects a page for replacement.
4. The selected page is removed and the required page is loaded into memory.
5. The process continues its execution.

1. FIFO (First-In, First-Out) Algorithm
In the FIFO page replacement algorithm, the page that entered memory first is replaced first.
It works like a queue: the oldest page is removed first.

Example: Consider 3 frames and the following page reference string: 1, 2, 3, 4

3123Fault

When page 4 is requested, page 1 is removed because it was the first page loaded into memory.
Advantage: Simple and easy to implement.
Disadvantage: It may replace an important page even if it is frequently used.

2. LRU (Least Recently Used) Algorithm
In the LRU page replacement algorithm, the page that has not been used for the longest period of time is replaced.
It uses the recent history of page references to decide which page should be removed.

Example: Consider 3 frames and the reference string: 1, 2, 3, 1, 4

When page 4 is requested, page 2 is replaced because it was the least recently used page.
Advantage: Generally performs better than FIFO because it considers recent usage.
Disadvantage: It is more difficult and costly to implement.

10. Explain allocation of frames. What is thrashing? Discuss its causes and methods for controlling thrashing.

In a paging system, physical memory is divided into fixed-size blocks called frames, while logical memory is divided into blocks called pages.
Page → fixed-size block of logical/virtual memory.
Frame → fixed-size block of physical memory.
Page size = Frame size.

When a process needs to be loaded into memory, its pages are placed into available frames.

Process Pages           Physical Memory

Page 0 ───────────────> Frame 5
Page 1 ───────────────> Frame 2
Page 2 ───────────────> Frame 8
Page 3 ───────────────> Frame 1

The pages do not need to occupy contiguous frames.
The operating system maintains a frame table to keep track of which frames are free and which are allocated.

Frame allocation process
A process is divided into pages.
The OS determines the number of frames required.
Free frames are identified.
Pages are loaded into available frames.
The page table records the mapping between pages and frames.
When the CPU generates a logical address, the MMU uses the page table to translate it into a physical address.

Types of Frame Allocation
Equal allocation: Every process receives an equal number of frames.
Proportional allocation: Frames are allocated according to the size of each process.
Priority allocation: Higher-priority processes may receive more frames.

Thrashing
Thrashing is a condition in which the system spends more time handling page faults and swapping pages than executing processes.
As a result, CPU utilization decreases and system performance becomes very poor.

Causes of Thrashing
Insufficient number of frames: A process does not have enough frames to hold the pages it frequently uses.
High degree of multiprogramming: Too many processes are kept in memory at the same time.
Frequent page faults: Processes continuously require pages that are not currently in memory.
Poor frame allocation: Processes may not receive enough frames according to their requirements.

Methods for Controlling Thrashing
Reduce the degree of multiprogramming: The number of processes in memory can be reduced.
Working Set Model: The OS allocates enough frames to keep the pages that a process is actively using.
Page Fault Frequency (PFF): The OS monitors the page fault rate and allocates additional frames when the rate becomes too high.
Proper frame allocation: Sufficient frames should be allocated to each process.

13. Explain disk structure and disk scheduling. Describe any three disk scheduling algorithms.

1. Disk Structure
A magnetic disk is a secondary storage device used to store large amounts of data. It consists of the following important components:
Platters: Circular disks on which data is stored.
Tracks: Concentric circular paths on the surface of a platter.
Sectors: Small divisions of a track where data is actually stored.
Read/Write Head: Used to read data from and write data to the disk.
Cylinder: A set of tracks located at the same position on different platter surfaces.

Disk Access Time
The time required to access data mainly depends on:
Seek Time: Time taken by the disk head to move to the required track.
Rotational Latency: Time taken for the required sector to rotate under the read/write head.
Data Transfer Time: Time required to transfer data between the disk and main memory.

Disk Scheduling
Disk scheduling is the technique used by the operating system to decide the order in which pending disk I/O requests are serviced.
Objectives of Disk Scheduling: Reduce disk head movement, Reduce seek time, Reduce overall access time, Improve disk performance, Provide fair service to requests.

Algorithms Example Context

Consider the following example: Request Queue: 98, 183, 37, 122. Initial Head Position: 53

A. FCFS – First-Come, First-Served
In FCFS, disk requests are serviced in the same order in which they arrive.
Service order: 53 → 98 → 183 → 37 → 122
Head Movement: 53→98=45, 98→183=85, 183→37=146, 37→122=85.
Total Head Movement = 45+85+146+85 = 361 cylinders.
Advantage: Simple and fair. Disadvantage: Can result in large head movement.

B. SSTF – Shortest Seek Time First
In SSTF, the request that is closest to the current head position is serviced first.
From 53, 37 is closest. Then 98. Then 122. Finally 183.
Service order: 53 → 37 → 98 → 122 → 183
Head Movement: 53→37=16, 37→98=61, 98→122=24, 122→183=61.
Total Head Movement = 16+61+24+61 = 162 cylinders.
Advantage: Reduces total head movement. Disadvantage: May cause starvation for requests far away.

C. SCAN – Elevator Algorithm
In SCAN, the disk head moves in one direction, servicing all requests along its path. When it reaches the end of the disk, it reverses direction and services requests in the opposite direction.
Assume disk range = 0–199, moving towards higher.
The head services: 53 → 98 → 122 → 183 → 199. Then it reverses: 199 → 37.
Head Movement: 53→98=45, 98→122=24, 122→183=61, 183→199=16, 199→37=162.
Total Head Movement = 45+24+61+16+162 = 308 cylinders.
Advantage: Provides uniform waiting time. Disadvantage: Head travels to the end even if no requests exist there.
